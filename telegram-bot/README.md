# Приветствие @NikolayTransportBot

Отдельный Cloudflare Worker для `/start`. Существующая визитка, её код, изображения, ссылки и Menu Button не меняются. Добавление этой папки в GitHub само по себе не запускает бота: требуется развернуть Worker и зарегистрировать webhook.

## Ответ

```text
Здравствуйте!

Я Николай. Более 15 лет работаю в грузоперевозках.

Помогаю перевозчикам с топливом, грузовыми шинами и загрузками.

Откройте визитку, выберите направление и напишите мне напрямую.
```

Inline-кнопка **«Открыть визитку»** открывает https://t.me/NikolayTransportBot/card . Она использует готовую ссылку Mini App; Menu Button не перенастраивается.

## Как работает

- `POST /webhook` проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` до чтения JSON. Он задаётся Telegram параметром `secret_token` при регистрации.
- Приветствие формируется только для личного `/start` от человека. Поддержаны `/start payload` и `/start@NikolayTransportBot`. Другие команды, групповые сообщения, редактирования и боты игнорируются.
- Worker возвращает JSON с `method: sendMessage`. Telegram выполняет этот метод при получении ответа webhook: https://core.telegram.org/bots/api#making-requests-when-getting-updates . Поэтому не нужны фоновая задача, компьютер, база или библиотеки.
- Результат исполнения такого sendMessage Telegram не возвращает. Реальный ответ обязательно проверяется вручную после подключения.
- `GET /setup` — отдельная служебная страница владельца для настройки с iPhone. Это не часть визитки. `POST /setup` защищён отдельным SETUP_KEY и допускает только check/connect.
- Токен бота на служебной странице не вводится: сервер читает его из Secret Cloudflare. Перед регистрацией проверяется правильный username бота.
- Код не вызывает setChatMenuButton, не рассылает сообщения, не сохраняет пользователей, chat ID или тексты. Каждый явный `/start` получает приветствие; учёт первого посещения не ведётся. При повторной доставке update Telegram возможен повторный ответ: exactly-once без хранения состояния не гарантируется.

## Секреты

Все значения добавляются в **Cloudflare → Worker → Settings → Variables and Secrets** с типом **Secret**, не Text:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | Токен @NikolayTransportBot из BotFather, без пробелов и переносов |
| `WEBHOOK_SECRET` | Случайные 20–256 символов A–Z, a–z, 0–9, `_`, `-` |
| `SETUP_KEY` | Другой случайный секрет такого же формата для владельца |

Страница /setup генерирует два независимых 43-символьных ключа локально через crypto.getRandomValues. Генератор ничего не отправляет серверу и не использует localStorage/sessionStorage. Сохраните ключи в менеджере паролей. Не помещайте токен и ключи в GitHub, исходники, URL или сообщения этого чата.

## Развёртывание и проверка

[Инструкция для iPhone](DEPLOY-IPHONE.md). Достаточно Cloudflare Workers Free. В рабочей среде нет Cloudflare-подключения и BOT_TOKEN, поэтому реальный Worker и webhook не развёрнуты и ответ в Telegram не проверен.

Тесты, Node.js 22+, без установки зависимостей:

```sh
cd telegram-bot
npm test
```

В тестах только вымышленные значения и имитация Telegram API. Проверяются точность приветствия и кнопки, авторизация, команды, личные чаты, ошибки, регистрация secret_token и отсутствие изменений Menu Button.

Для CLI при наличии авторизации Cloudflare:

```sh
npx wrangler deploy
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put SETUP_KEY
```

Значения вводятся в защищённых запросах, не в аргументах команд. Затем откройте публичный адрес Worker с /setup и подключите webhook.

## Логи и данные

В коде нет console.log и журналирования запросов, пользователей, секретов или необработанных ошибок. Telegram API требует токен в адресе служебного HTTPS-запроса: этот адрес не выводится в ответы и отчёты. В wrangler.jsonc отключена Observability. При ручном создании через Dashboard также отключите Workers Logs/Observability и не подключайте Logpush или журналирование исходящих запросов.

`.dev.vars`, `.env` и рабочие файлы Wrangler исключены из Git. Исходные PNG визитки и все её настройки остаются прежними.

После настройки можно удалить Secret SETUP_KEY, если служебное управление больше не нужно: приветствие продолжит работать с BOT_TOKEN и WEBHOOK_SECRET. Для повторной настройки добавьте SETUP_KEY снова.
